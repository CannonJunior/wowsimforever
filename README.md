# WoW Forever DPS & Burst Simulator

Plan: `docs/PLAN.md`. Phase 1 engine bring-up is in progress; see "Status" below.

## Workspace layout

- `crates/data` — versioned, confidence-tagged data pack types (`DataPack`, `SpellDef`, `DemonicSacrificeEffect`, `DisputedMechanic`, dispute ledger). See Plan Section 3, Principles 1/2/13.
- `crates/stats` — shared Monte Carlo output statistics (`DpsStats`, `stats_from`), used by both `crates/engine` and `crates/burst` so distributions are reported the same way everywhere.
- `crates/engine` — the Monte Carlo single-target simulation engine. See Plan Section 7. `SpellDef` now carries an `ap_coefficient` alongside the existing spell-power `coefficient`, so real attack-power-scaling special abilities (e.g. Warrior's Bloodthirst: 45% Attack Power + 48 flat) can be sourced, not just auto-attack. The "rotation exhausted" panic now only fires for a truly empty rotation with no weapon either — a rotation that's entirely cooldown-gated abilities (Bloodthirst alone) correctly waits (auto-attacking in the background) rather than panicking, unified with the existing mana-wait logic. Enforces an optional mana constraint (`BuildConfig::starting_mana`/`mana_regen_per_second`, Phase 1 simplification closed): `None` preserves the original unconstrained behavior exactly; `Some(m)` starts the fight with `m` mana, enforces each cast's `resource_cost`, and waits (regenerating) rather than panicking once nothing in the rotation is affordable. Also models attack-power/weapon-damage classes (`BuildConfig::attack_power`/`weapon_min`/`weapon_max`/`weapon_speed_ms`): an empty `rotation` is legitimate (no panic), and a non-zero `weapon_speed_ms` schedules real auto-attack events on their own independent weapon-speed timer (not gated by the GCD-based rotation loop, matching the real mechanic), using the classic `attack_power / 14 * swing_time` formula. This is what makes Hunter/Rogue/Warrior runnable at all — see the class-coverage note below.
- `crates/gear` (`wowforever-gear`) — a minimal gear/itemization mechanism (Phase 1's "hand-entered gear only" simplification, partially closed): computes `spell_power`/`crit_chance` from a list of equipped items instead of requiring them typed in directly. Ships no real item database (out of scope); `data-packs/gear.example.json` is a placeholder-tagged demo file, never loaded except via the CLI's explicit `--gear <path>` flag.
- `crates/storage` — historical results storage (Plan Section 4.3): an append-only, build-fingerprinted run store with regression detection across data-pack versions.
- `crates/burst` — the Burst Damage Rotation Calculator (Plan Section 4.6): finds the expected-damage-maximizing ability sequence within a short, fixed PvP window via beam search, with the floor (no-crit) damage reported as a stat of that *same* sequence. Deliberately separate from `crates/engine` (a distinct simulation mode, per the plan).
- `crates/cli` (`forever-sim` binary) — bring-up CLI: `--mode dps` (default) runs the steady-state DPS demo; `--mode burst` runs the burst calculator.
- `crates/ingest` (`wowforever-ingest` binary) — fetches a thewowdb.com/wow-forever spell page and emits a `SpellDef`-shaped JSON object (confidence `beta-datamine`), ready to paste into a data pack after review. Parsing is unit-tested against saved real-HTML fixtures (`crates/ingest/tests/fixtures/`), independent of network access. Usage: `cargo run -p wowforever-ingest --bin wowforever-ingest -- --spell-id 11661 --id shadow_bolt --name "Shadow Bolt"`.
- `crates/recommend` — the Change-Driven Recommendation Engine (Plan Section 4.4): diffs two data packs field-by-field and cross-references the result against `crates/storage`'s history to find which previously-run builds reference a changed spell ("builds worth re-testing"). Wired into the CLI as `--mode recommend`.
- **External-sim comparison (Plan Section 4.2)** — `crates/storage`'s `ExternalResultStore` and `build_comparisons`, wired into the CLI as `--mode add-external` (record a result you read off another site yourself) and `--mode compare-external` (view it alongside our own simulation of the same build). User-pasted only, per the plan's legal review (Section 0.2) — there is no scraper, and never will be one here without the site's permission.
- **`crates/wasm`** — compiles the real DPS engine and burst calculator to `wasm32-unknown-unknown` for genuine client-side compute (Plan Section 5). Core logic lives in plain, natively-testable functions; the `#[wasm_bindgen]` wrappers are thin pass-throughs.
- **`web/`** — the client-side frontend: confidence-tag badges/warnings (Plan Section 5's UI treatment), and a client-side-only anonymous identity model (Plan Section 5's "accounts," deliberately scoped to avoid server-side privacy complexity — there's no server). Run `./start.sh` from the repo root to build and serve it (see `web/README.md` for what that does and the manual steps if you need them).
  - **`web/talents.html`** — a real talent calculator for **all 9 classes**, visually and functionally modeled on arenamaster.io's Forever talent calculators: three tree columns per class, a 7×4 icon grid with real Wowhead-CDN icons, left-click to add a point / right-click to remove, tier gating (every 5 points) and talent-to-talent prerequisites enforced live, a 51-point budget, save/load named builds to `localStorage`, and a "Run this build through the simulator" button right on the page. Data is `data-packs/talents.<class>.json` (`community-reported` — see each file's own `source_note` for exactly how it was sourced; icon-verification coverage varies by class, honestly tracked per-talent via `icon_verified`).
  - **Results tabs** — after running DPS/HPS from **either** `index.html`'s "Run Simulation" button or `talents.html`'s own "Run DPS"/"Run HPS" button (both wired identically as of the twenty-sixth update — the two pages previously drifted, with the tabs only reachable from `index.html`), shows Abilities (per-ability DPS/share/casts/avg-per-cast/crit%, Direct and DoT-tick components reported as separate lines), Timeline (a real per-event chart, one row per ability, hoverable marks showing exact time/damage/crit), and Buffs & Debuffs (uptime bars; an honest "none modeled" message for classes with no buff mechanic). All three come from `wowforever_engine::simulate_detail` — one real, seed-fixed representative run, explicitly labeled as such and *not* averaged across the 10,000-iteration Monte Carlo summary the Overview tab shows, because you can't coherently average "which rolls crit" into one timeline.
  - **`web/talent-builds.js`** — the shared module both `talents.html` and `index.html` import, so a build saved on the talent calculator is immediately loadable from the simulator's own build selector (and vice versa) instead of two pages drifting out of sync. Exports `CLASS_SIM` (per-class rotation/mode/talent-to-field mapping — the single source of truth for what's runnable and what each talent actually does to a build), the shared `localStorage`-backed saved-build store, and `buildSimConfig`/`buildBurstConfig` (translate a class id + talent allocation into a real `BuildConfig`/`BurstBuildConfig`). `index.html`'s build dropdown now lists a "demo build" per runnable class plus every saved talent build (grouped, with non-runnable ones shown but disabled rather than hidden) — selecting a saved Warlock build with Demonic Sacrifice invested and running DPS or Burst from `index.html` reproduces this project's exact existing golden-test DPS value, verified in a real headless-Chrome session, not just asserted. The simulator's runnability is honestly scoped per class either way: Warlock maps Demonic Sacrifice/Demonic Pact to real engine fields; Mage/Shaman/Priest/Paladin run a real baseline rotation with a stated "no talents currently affect this number" note; Druid/Hunter/Rogue/Warrior have no runnable rotation at all (Druid's only sourced spell has no filler; Hunter/Rogue/Warrior deal zero spell-power-scaling damage in Classic-era itemization), surfaced as a disabled option with the reason shown, not hidden.
- Mage (Fireball, Frostbolt), Priest (Flash Heal, Greater Heal, Renew), Druid (Moonfire), Shaman (Lightning Bolt), and Paladin (Holy Light) added alongside Warlock — real sourced data, proving the pipeline generalizes beyond one class (Plan Section 7's "remaining classes/specs"). **Hunter, Rogue, and Warrior are deliberately not represented**: in Classic-era itemization, which WoW Forever preserves, these three classes deal 100% attack-power/weapon-damage-scaling damage with zero spell-power-scaling abilities, so this engine's `base + coefficient × spell_power` formula has nothing real to attach to any of their spells — adding an entry would mean fabricating a coefficient, which the no-placeholder rule below forbids. Representing them needs a different damage model (attack power, weapon dice, armor mitigation) that doesn't exist here — see `docs/PLAN.md`'s seventeenth update.
- **`crates/raid`** — Phase 3 (Plan Section 8): aggregate raid DPS from independently-simulated members, aggregated the statistically correct way (summing same-iteration samples per member before taking percentiles, not summing each member's independently-computed percentiles). Also models shared raid **debuffs** with a slot cap and real cross-character synergy (`simulate_raid_with_debuffs`): a sourced Warlock curse (Curse of the Elements) applied to the target increases every raid member's damage of the affected schools, correctly handling mixed-school rotations via `wowforever-engine::simulate_samples_by_school`. Debuff ids are deduped and capped at `CLASSIC_DEBUFF_LIMIT` (16, sourced from Classic WoW's real debuff-slot cap). Still does not model raid-wide *buffs* (stat boosts) — see the crate's module docs for why. Wired into the CLI as `--mode raid`.
- **`crates/heal`** — Plan Section 8's healing-throughput model, both halves. Healer **output** (`simulate_hps`) is a thin, honestly-labeled wrapper around `wowforever-engine::simulate` (healing math is identical to damage math in this data model — base + coefficient × spell power, same crit/GCD/tick scheduling), not a duplicate engine, for Priest (Renew, Flash Heal). **Incoming raid damage** (`evaluate_healing_sufficiency`, `SyntheticIncomingDamageProfile`) is modeled as an explicit, caller-supplied, named assumption — never sourced, never defaulted — since no real WoW Forever encounter-damage data exists for a game that hasn't launched; the comparison itself is a real per-iteration Monte Carlo check, not a mean-vs-mean shortcut. Wired into the CLI as `--mode heal` (prints a loudly-labeled illustrative profile) and into the web frontend (Priest option).
- `tools/wowhead-curation-bookmarklet.js` — a browser bookmarklet that assists manually curating spell data from sites that block automated fetching (e.g. Wowhead). See `tools/README.md`; prefer `crates/ingest` for anything thewowdb.com covers.
- `data-packs/forever-beta-2026-10-17-rev6.json` — **the production data pack, loaded by default.** Never overwritten in place — each revision is its own file (`rev2` through `rev6`), per `CLAUDE.md`'s versioning convention. Most spell entries are `beta-datamine` (direct extraction via `crates/ingest` against thewowdb.com's own client-data-cited pages); the one `raid_debuffs` entry (Curse of the Elements) is `community-reported`, see `docs/PLAN.md`'s sixteenth update for why. Contains **no placeholder values** (see "Placeholder-data policy" below).
- `data-packs/overrides.example.json` — a demonstration overrides file containing one clearly-synthetic placeholder spell. Never loaded unless `--overrides` is passed explicitly.

## Placeholder-data policy

See `CLAUDE.md` for the full rule. Short version: the production data pack never contains placeholder/synthetic values — if a real coefficient isn't known yet, the entry is omitted, not guessed. Placeholder data can only enter a run via an explicit, required `--overrides <path>` argument:

```
cargo run --bin forever-sim                                              # production data only, no placeholders possible
cargo run --bin forever-sim -- --overrides data-packs/overrides.example.json   # explicit opt-in, loudly flagged in the output
```

## Running it

```
cargo test                                                  # unit tests, dispute-delta correctness properties, golden-file regression tests
cargo run --bin forever-sim                                 # run the demo build against the production data pack
cargo run --bin forever-sim -- --history <path>             # also persist this run and check it against the same build's prior run under a different data-pack version
cargo run --bin forever-sim -- --show-history <path>        # print a trend view of everything recorded at <path>, with no new simulation
cargo run --bin forever-sim -- --mode burst                 # run the burst damage rotation calculator instead of the DPS demo
cargo run --bin forever-sim -- --mode recommend --from <old pack> --to <new pack> --history <path>   # diff two data packs and find builds worth re-testing; add --resimulate to actually re-run them
cargo run --bin forever-sim -- --mode add-external --external <path> --build <full fingerprint from --show-history> --source <name> --dps <value>   # record a result you read off another site yourself
cargo run --bin forever-sim -- --mode compare-external --history <path> --external <path>   # view your own result next to every external one recorded for the same build
cargo run --bin forever-sim -- --mode raid   # aggregate DPS for a toy 2-person (Warlock + Mage) raid, with Curse of the Elements synergy
cargo run --bin forever-sim -- --mode heal   # Priest (Renew + Flash Heal) HPS, plus a synthetic healing-sufficiency demo
cargo run --bin forever-sim -- --gear data-packs/gear.example.json   # replace the demo build's hand-typed stats with gear-computed ones (placeholder items, demo only)
```

## Known gaps (tracked, not hidden)

- `crates/engine/tests/differential_wowsims.rs` cross-validates this engine's damage-formula *structure* (additive base + coefficient × spell power) against `wowsims/classic`'s own published source for a classic-era Shadow Bolt rank. It does **not** run their binary or validate WoW-Forever-specific numbers against theirs — `wowsims/classic` simulates a different game variant (Classic Season of Discovery), so its numbers are expected to differ from Forever's rebalanced ones. See the test file's module docs for the full reasoning and exact sources cross-checked.
- **Rotation is still a simplified, hard-coded priority order, not the full APL expression grammar envisioned in Plan Section 2.2/3** — deliberately not attempted in this pass. A real APL interpreter (conditional expressions referencing resource levels, buff/debuff state, cooldowns) is a multi-day engineering investment in its own right; a narrow bolt-on (e.g. a single mana-threshold gate hard-coded per spell id) was considered and rejected as not generalizing to anything beyond itself — see `docs/PLAN.md`'s eighteenth update for the full reasoning. What *did* ship this pass, and genuinely interacts with rotation selection now: the mana constraint below.
- **No accounts/storage beyond what Phase 2 already built** (client-side-only identity, append-only local history) — a hosted backend remains out of scope.
- Resource (mana) modeling and gear-stat computation are now real, see `crates/engine` and `crates/gear` above — both are honestly-scoped partial closures of Plan Section 7's Phase 1 cut, not the full itemization/resource systems a mature sim has (no real item database, no spirit-based regen-with-5-second-rule mechanics, no mana cost reduction from talents/gear).
- The production data pack's spell values are mostly `beta-datamine` (direct client-data extraction via thewowdb.com) for Warlock/Mage/Priest; Druid/Shaman/Paladin's spells are `community-reported` (thewowdb.com was unreachable during that sourcing pass — see `docs/PLAN.md`'s seventeenth update). **Hunter, Rogue, and Warrior still have no spell entries at all** — these three classes deal zero spell-power-scaling damage in Classic-era itemization, so there is no honest spell-power coefficient to source for them — but all three are runnable now via the attack-power/auto-attack engine extension (hand-entered `attack_power`/weapon stats, no special abilities sourced yet). All 9 classes are runnable through the simulator/talent calculator as of the twenty-second update.
- The burst calculator has no execute/low-target-health damage bonus modeling. Shadowburn's real-game role is as a kill-confirm tool that gets much stronger against a low-health target (and, per talent, can refund a Soul Shard) — against the full-health opponent profile this bring-up demo uses, the optimizer correctly weighs it against Shadow Bolt/Immolate/Corruption on raw expected value alone, which is a real result given what's modeled, not a bug, but it means the calculator doesn't yet answer "what's the best execute sequence," only "best sequence against a target at full health."
